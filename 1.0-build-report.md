## Earlier candidate source and publication dependency

The source working tree was inspected before building. Its HEAD was
`055a44d8e771940aedbabf0c64a061fc7caf173c`, with extensive dirty changes
including version definitions in `firmware/src/ui.c`, chord/arp/controller
changes, A2DP hooks and untracked `firmware/src/ble/a2dp*` files.

The actual working-tree firmware was compiled, rather than fetching the old
pinned revision. Both versions are confirmed through each Wasm module's
`emu_version()` export and `build-info.json`.

At that earlier stage, `ORBIT_REVISION` still held the baseline. The
candidate metadata truthfully reported `dirty: true` and
`local_development: true`; the baseline commit alone could not reproduce
those modules. The final build above replaced the candidate artifacts,
pin, page copy and documentation links before publication.

## Changes

The old browser HAL failed to link against the current 1.0.B firmware with
undefined `a2dp_link` and `a2dp_mix`. The browser has no Bluetooth audio input:
the HAL now reports no phone connection and contributes no phone PCM. This
keeps BT AUDIO hidden and preserves the existing honest radio error.
Its master ADC also updates the firmware's new `master_k10` value.

The selector, URL routing, page title, manifest and cache keys now use
1.0.0 / 1.0.B. Both old save keys remain unchanged: `image-orbit` and
`image-orbit-0.9.B`. The 1.0.B delay expectation is 16,384 samples, matching
the actual current firmware. Copy describes chord voicings, arp continuity,
controller toggles/CC feedback and the limits of browser Bluetooth support.

## Browser checks

The candidate was served with:

```sh
python3 -u -m http.server 8788 --bind 127.0.0.1 --directory dist
```

An owned headless Chrome profile was driven using OmOWright
`connectPipe`, `emulate(page, 'desktop-1440')` and
`emulate(page, 'iphone-14')`. Both versions were selected with
`page.locator('#firmware-version').selectOption(...)` and powered on with
`page.locator('#power').click()`.

Observed results:

- Both versions boot a real AudioWorklet at 44,100 Hz. Before POWER, no
  AudioContext exists. Switching versions restores that power gate.
- Holding keyboard A generated finite analyser PCM with a measured peak of
  0.461395263671875 in both fresh default sounds.
- An EDIT tap changed the actual firmware canvas.
- Both versions have no horizontal overflow at 1440 x 900 or 390 x 844.
  Phone emulation used DPR 3 and five touch points. Its selector occupies
  y=10..54; the rotated instrument occupies y=64..844 without overlap.
- Actual IndexedDB contains both separate 458,752-byte save images.
  Returning to 1.0.0 loads its existing 458,752-byte image and boots again.
- Desktop has one document scroller; the existing compact instrument
  layout is preserved.

Fresh screenshots are under ignored `dist/`:
`1.0.0-desktop-1440.png`, `1.0.0-phone-390.png`,
`1.0.B-desktop-1440.png`, `1.0.B-phone-390.png` and
`1.0.0-restored-desktop-1440.png`.

Two QA probe issues were diagnosed without changing production behavior:
an initial one-shot frame listener consumed a LED message, and a 15-second
autosave probe was shorter than the firmware's 20-second save interval.
Direct canvas/PCM checks and later actual IndexedDB reads confirmed both
paths. The BLE phone capture was recaptured after reapplying phone
emulation following navigation; its final PNG is 1170 x 2532.

The browser and local servers were stopped. An independent nested reviewer
could not be launched because this task is already at the agent nesting
limit. Screenshots were inspected directly. This was functional and
responsive QA, not a full WCAG certification; the existing dark-only shell
and physical-panel accessibility limits remain. Editor LSP services were
unavailable, but actual clang compilation and all runtime tests passed.
FM-1 timing, Bluetooth MIDI and A2DP behavior are not established by these
browser checks.
